# Message Lifecycle Audit — Phase 4.5

Scope: verify the CRM truth path from webhook/event to persistence, lead linking, inbox, conversation timeline, and qualification inputs. This audit is limited to the existing lead knowledge store and existing webhook/extension stores. No database schema changes were made.

## Conversation Contract

Explicit selectors now define what each visible surface may consume:

- `conversationMessages(messages)`
  - inbound customer messages
  - outbound customer messages
  - excludes hidden records
  - excludes notes and system records
- `internalNotes(messages)`
  - user notes
  - AI notes
  - excludes hidden records
- `systemEvents(messages)`
  - worker events
  - task events
  - audit events
  - sync events
  - excludes hidden records

System events must not feed Conversation Timeline, Inbox Preview, Recent Comms, or Qualification Inputs. They belong in Activity, Tasks, or Audit-only views.

## Findings

### Orphan messages
- Stabilization tests verify WhatsApp webhook records produce a linked lead and conversation.
- No orphan customer message was found in the tested lifecycle path.

### Duplicate messages
- Duplicate webhook deliveries are deduped by stable message IDs in the existing lead knowledge persistence path.
- Added test coverage for duplicate WhatsApp delivery dedupe.

### Hidden messages
- Hidden messages remain excluded by the new selectors.
- Hidden records do not appear in Inbox or Timeline selectors.

### Unlinked messages
- WhatsApp webhook path tested: stored message includes lead ID and conversation ID.
- If a future source bypasses the lead knowledge store and lacks lead/conversation linkage, it should be marked invalid and blocked from qualification.

### Duplicate webhook deliveries
- Existing persistence dedupes by message identity.
- Added Phase 4.5 test confirms one visible customer message after duplicate delivery.

### Timeline-only records
- Worker/system records previously risked appearing as timeline records because `lead.messages` mixed directions.
- Fixed by routing visible timeline data through `conversationMessages`.

### Inbox-only records
- Inbox now builds lead-backed previews through `buildLeadBackedInboxItems`, which dedupes by message ID and only consumes `conversationMessages`.

## Root Cause Addressed

The existing `LeadKnowledgeMessage.direction` union contained customer messages, notes, and system records in one array. Some surfaces used the array directly. Phase 4.5 introduced explicit selectors and changed visible conversation surfaces to consume only customer messages.
